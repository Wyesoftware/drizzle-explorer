# Drizzle Explorer — notes for agents

DBeaver-like desktop DB explorer. **Pure Bun**: no Electron/Node. See README.md for the stack.

## Layout
- `src/main/` — Bun main process. `index.ts` opens the webview (blocks the thread), `worker.ts` is the backend Worker. The packaged backend listens on a random free port, so the UI must not rely on localStorage (origin = port): persisted UI state (settings, column formats, theme) goes through `lib/prefs.ts` → `ui.state`/`ui.setState` → `server/prefs.ts` (`ui-state.json` in the config dir). `main.tsx` awaits `loadPrefs()` before importing `App` so zustand stores hydrate synchronously from the cache; use `storage: createJSONStorage(() => prefsStorage)` for any new persisted store. `system.info.build` carries the build time (`--define` in `scripts/build.ts`) so stale builds can be told apart.
- Export of a table can use a custom projection: `ExportRequest.columns` (`ExportColumn { name, source | expression }`) → `TableRowsRequest.select` → `drivers/select.ts` builds `"col" as "name", (expr) as "name"`; such reads return no key columns.
- Import/transfer mapping is per *target* column (`ColumnMapping { target, source | expression }`): a column can take a source value or a raw SQL expression evaluated by the target DB per row; `InsertOptions.onConflict` (error/ignore/update) becomes `ON CONFLICT … DO NOTHING / DO UPDATE SET col = excluded.col` on the primary key (`conflictClause` in `drivers/upsert.ts`, shared by both drivers).
- `src/server/` — backend: `rpc.ts` (method table), `drivers/{postgres,sqlite}.ts` (+ `filters.ts` WHERE builder), `connections.ts` (store + live drivers), `transfer.ts` (export/import/copy rows, `formats/`), `dump.ts` (pg_dump/pg_restore/psql + SQLite native dump), `jobs.ts` (background job registry polled by the UI), `static.ts`.
- `src/main/macos-menu.ts` — builds the NSMenu through `bun:ffi` + the Objective-C runtime; without it Cmd+C/V do nothing in WKWebView.
- `src/shared/types.ts` — the RPC contract (`RpcMethods`). Add a method here first, then implement in `rpc.ts`, then call via `rpc()` in the UI.
- `src/ui/` — React (Vite root). `features/*` by screen, `components/ui/*` are generated shadcn (Base UI) components — edit via `bunx shadcn add`, not by hand when possible.
- Column display formats live in `lib/format-value.ts` (pure, unit-tested with `bun test`) and the persisted `lib/formats.ts` store; `DataGrid` applies them via `cellRendererParams`, `GridHeader` is the custom AG Grid header with the ⋯ menu.
- Row editing: `TableTab` keeps unsaved edits in `usePendingChanges` (inserts/updates/deletes keyed by row id), overlays them on the fetched page, and sends `data.mutate` (one transaction, each update/delete must hit exactly 1 row). Row id = JSON of `keyColumns` values from `data.rows` (PK, or hidden `__key` = ctid/rowid); when there is no key (views, PK-less tables) rows get positional ids (`@<offset>`), because AG Grid renders rows by id and duplicate ids freeze the viewport in infinite mode. Columns starting with `__` are hidden by `DataGrid`.
- Column filters: `DataGrid` takes `columnFilters` (`GridColumnFilters`: `filterFor`, `model`, `onModelChange`) and renders a floating filter row with our own filter components (`features/grid/filters/`: `ColumnFilter` popup, `ColumnFloatingFilter`, `model.ts`). They never filter client-side (`doesFilterPass` always passes): the grid's filter model (column → `FilterSpec` without `column`) is owned by `TableTab` (`filterModel`, survives the remount when toggling infinite scroll), turned into `FilterSpec[]` with `toFilterSpecs` and merged with the filter bar into `effectiveFilter` (page requests, export source, "(filtered)" count). In infinite mode the grid resets its own cache on filter changes and passes `filterModel` to `getRows`, so column filters are *not* part of the datasource `version`. `TableTab.filterFor` picks the UI: set filter (PK, single-column FK, enum, boolean; values from `data.distinct` → `Driver.distinctValues` → shared `drivers/distinct.ts` query; for FK columns the referenced table is joined so each value carries a label from its text columns (`pickLabelColumns`, same choice as the lookup editor) and the search matches labels too; labels live in the UI-only `ColumnFilterModel.labels`, stripped by `toFilterSpecs`; "(NULL)" entry → `FilterSpec.orNull`), number, date (`dateEditMode`), else text. `FilterSpec.values` is the explicit list for `in`. AG Grid options passed to `AgGridReact` must be referentially stable (module constants / memos): a fresh object per render re-applies the option and, in the infinite row model, resets the cache after every load.
- Every `DataGrid` starts with a running row-number column (`ROW_NUMBER_COL` = `__row_number`, pinned left, value = display index + `rowNumberOffset`; `TableTab` passes the page offset in paged mode). It is hand-rolled because AG Grid's `rowNumbers` option needs the Enterprise `RowNumbersModule`; cell callbacks ignore that column. Column filters can also run client-side: `GridColumnFilters.clientSide` makes `ColumnFilter` evaluate the model in `doesFilterPass` with `filters/model.ts` `matchesModel` (unit-tested, mirrors the server WHERE semantics) and `onModelChange` then receives the displayed row count. `SqlTab` (explore SQL tabs and the assistant playground alike) uses that: `filterFor` picks number/date/text from the result column type (or a numeric sample when the type is unknown), the model resets on every run, and the toolbar shows "N of M rows (filtered)".
- Cell editors are chosen in `TableTab.editorFor` (enum/boolean/date/lookup/text) and mapped to AG Grid colDefs in `DataGrid.editorColDef`; custom editors live in `features/grid/editors/` and use the ag-grid-react `CustomCellEditorProps` (`onValueChange` + `stopEditing`). FK pickers call `data.lookup` (server-side OR search over key + text columns).
- AI assistant: `server/ai/sessions.ts` runs each turn through `@anthropic-ai/claude-agent-sdk` `query()` (resumed Claude Code session per chat, `tools: []` so only our MCP tools exist, `allowedTools: ["mcp__db__*"]`), streams `AiEvent`s to the UI over SSE (`GET /ai/events?id=` in `worker.ts`), and persists chats to `ai-sessions.json`. Tools live in `server/ai/tools.ts` and must stay read-only (`executeReadOnly`, `fetchRows`); UI actions are events, not tool side effects. UI: `features/ai/AiPanel.tsx` + `lib/ai-store.ts`. Rule from the user: the assistant must never show data or SQL in chat; tools emit `playground_query` events that fill the per-session playground (store `playgroundQuery`; its SQL child is a nested `SqlTab` addressed through `updateTab`, auto-run via `runVersion`; see the two-mode layout below). Settings (`ai-settings.json`: auth mode subscription/apiKey + stored key, default model/effort) and account info (`claude auth status --json`, cached 60 s) are served by `ai.status`; API-key mode injects `ANTHROPIC_API_KEY` into the SDK `env`, subscription mode strips it. Rate limits come from SDK `rate_limit_event`s. The model list and plan name come from a token-free CLI probe (`probeCli`: `query()` with a never-yielding prompt stream, then `supportedModels()` / `accountInfo()`, then `close()`; cached 5 min, reset when settings change). Base UI menus: a `DropdownMenuLabel` must sit inside `DropdownMenuGroup` or it throws. The panel connects the SSE stream *before* calling `ai.send` so the first events of a new chat are not lost. SQL is pretty-printed client-side with `lib/sql-format.ts` (`sql-formatter`; `bun fmt` has no SQL support). The system prompt enforces prose-only chat and `Markdown.tsx` collapses any code block as a safety net. In the compiled app the SDK's native binary is absent, so `resolveClaudeExecutable()` points it at the user's `claude` CLI.
- Settings are a full-page overlay, not a tab (`features/settings/SettingsPage.tsx`, rendered by `App.tsx` over the panel group while `useAppStore.settings` holds a section; `openSettings(section)` / `closeSettings()`, Escape or ✕ closes; sections general/table/assistant/updates; `AssistantSettings.tsx` holds the former assistant dialog). The app has two exclusive modes (`lib/layout.ts` `mode`, persisted, Cmd/Ctrl+J toggles, `components/ModeSwitch.tsx` segmented control + settings gear in each mode's header): `explore` = connections sidebar + table/SQL/routine tabs (`Workspace.tsx`), `assistant` = `features/ai/AssistantMode.tsx` with three panes: the chat thread list (`features/ai/ThreadList.tsx`: title, latest-reply preview, connection, ⋯ menu with rename / connection / delete; collapsible to `ThreadRail`, width persisted), the chat (`AiPanel`, header = title + connection badge, no session select), and the active chat's playground (`features/playground/PlaygroundTab.tsx` `PlaygroundPane`), nothing else. Session actions shared by these panes live in `features/ai/session-actions.ts` (`loadSession`, `createChat`, `deleteChat`, `configureSession`) and use the module-level `lib/query-client.ts`. Sessions persist `connectionId` and expose a `preview` = the user's first request (`AiSessionInfo`; `ai.configure` also takes `title`/`connectionId`). The title is the raw request only until the first turn ends: `generateTitle` then runs a one-shot haiku `query()` (no tools, no resume, `cleanTitle` sanitises) and emits `session_updated` so the UI refetches `ai.sessions`; `Session.autoTitle` guards it and a user rename (`configure({ title })`) clears it. `SqlTab` runs are sequenced (`runSeq`): only the most recently started execution publishes its result, because the assistant fires several `run_query` calls per turn and a slow earlier one must not overwrite the final playground result; the chat's connection = session.connectionId, mirrored into the playground SQL editor, and changes on the playground side are written back through `ai.configure`. Playgrounds are *not* tabs: `useAppStore.playgrounds` (by session id, `Playground { sessionId, title, connectionId, sql: SqlTab }`); `updateTab` also patches a playground's nested SQL editor by its id, `removePlayground` on chat delete. The chat's context is always the playground's connection + SQL (no opt-out checkbox); the connection selector under the prompt (`AiPanel` `selectConnection`) writes to the playground's SQL editor via `updateTab`, so both sides stay in sync, and a `draftConnectionId` covers the moment before the first message creates the session; amber = no connection chosen. The assistant panel has no settings buttons by design, and the status bar only keeps the theme toggle and the update link. Panel layout is persisted in `lib/layout.ts` (`drizzle-explorer.layout`: `mode`, `sidebarCollapsed`, `sidebarWidth`, `aiWidth`, `threadsCollapsed`, `threadsWidth`); the collapsed sidebar is replaced by `SidebarRail` (Cmd/Ctrl+B toggles), and panel widths are pixel `defaultSize`s with `groupResizeBehavior="preserve-pixel-size"` + `onResize`. The macOS menu has About / Check for Updates… / Settings… (Cmd+,): `macos-menu.ts` registers an NSObject subclass whose methods are `JSCallback`s, `index.ts` forwards the action with `webview.eval` as a `drizzle:menu` CustomEvent, and `lib/menu-events.ts` handles it (plus Ctrl/Cmd+, on other platforms). App preferences live in `lib/settings.ts` (zustand persist v2: table mode, page size, update checks; the release repository is the `UPDATE_REPO` constant in `shared/types.ts`, not a setting); theme in `lib/theme.tsx`; dialog in `features/settings/AppSettingsDialog.tsx`. Infinite scroll uses AG Grid's infinite row model via the `datasource` prop of `DataGrid` (change `version` to refetch; filters are part of it). Editing works there too: the block cache owns the rows, so unsaved values are overlaid through `GridEditing.pendingValue` (valueGetter) instead of replacing `rows`, `rows` becomes `pinnedTopRowData` for unsaved inserts, and the datasource stamps `__rowId` on every block row (the grid asks for ids before React re-renders with `keyColumns`) and records originals in a ref map. AG Grid cannot change `rowModelType` after init, so `DataGrid` remounts `AgGridReact` with a `key` when toggling. Version/update helpers are in `server/app.ts` (`APP_VERSION` from package.json, GitHub releases API; pure helpers + tests in `server/versions.ts`). `app.installUpdate` is a job: download the `drizzle-explorer-<ver>-<platform>-<arch>` asset, verify its `.sha256`, extract, swap the `.app`/executable next to the running one (rename, old copy removed by `cleanupAfterUpdate` on next start), spawn the new copy, then `process.kill(pid, SIGTERM)` because the main thread is blocked in `webview.run()` (a worker's `process.exit` only ends the worker). `DRIZZLE_EXPLORER_GITHUB_API` overrides the API base for testing against a local mock. Release automation: `.github/workflows/release.yml` + `scripts/set-version.ts` (tag → package.json), `scripts/package.ts` (asset naming + checksum; keep in sync with `versions.matchAsset`), `scripts/macos-sign.sh` (Developer ID signing with `scripts/macos/entitlements.plist`, notarization, stapling; signs webview-bun's dylib before the build so the embedded copy is signed).
- SQL library (`server/queries.ts`, `queries.json` in the config dir; `SavedQuery`): named queries per connection (`threadId: null`; RPC `queries.list/save/delete`, hooks `useSavedQueries/useSaveQuery/useDeleteQuery`, react-query key `["queries", connectionId]`) plus one unnamed entry per assistant chat (`threadId` = session id) holding the playground's latest SQL. Named ones show under each connection in the sidebar ("Saved queries" group in `ConnectionNode.tsx`: open → `openSavedQuery` tab `saved:<id>` with `SqlTab.savedId`, rename/delete via menu) and in `SqlTab`'s toolbar (Save = update the linked entry or open `saveQuery` dialog → `features/sql/SaveQueryDialog.tsx`; bookmark menu loads one into the editor or "Save as new…"). The playground is never linked: Save there always adds a named copy. Chat entries: the server writes them when a tool emits `playground_query` (`queries.setThread` in `runTurn`), `ai.session` returns the entry as `query` and `loadSession` restores it into an empty playground, edits are pushed from `PlaygroundPane` through `syncThreadQuery` (debounced, guarded by `knownThreadSql` so an unloaded/empty editor never overwrites the server; `markThreadQuery` records assistant-written SQL), `ai.delete` removes the entry, and `connections.delete` drops the connection's named queries. Explore SQL tabs themselves are still not persisted.
- App-level dialogs (export/import/transfer/confirm/dump/restore/job) go through `lib/dialogs.ts` + `features/dialogs/DialogHost.tsx`; open them with `openDialog({ kind, ... })` from anywhere (tree context menus do this).
- `src/main/assets.generated.ts` — committed placeholder; `scripts/build.ts` rewrites it during build and restores it.
- App icon: `assets/icon.svg` → `bun run icon` (`scripts/make-icon.ts`, needs rsvg-convert or ImageMagick + sips/iconutil) → committed `assets/AppIcon.icns` + `assets/icon-1024.png`. `build.ts` copies the icns into `Contents/Resources` (`CFBundleIconFile`); from source, `index.ts` sets the Dock icon via `setMacosDockIcon` (NSImage + `setApplicationIconImage:`).
- Signing: `bun run build` = `build.ts --sign` → `scripts/macos-sign.sh sign`, which picks `CODESIGN_IDENTITY`, else the login keychain's "Developer ID Application", else "Apple Development" (trusted on this Mac only), else ad-hoc; notarization only for Developer ID + `APPLE_ID`/`APPLE_TEAM_ID`/`APPLE_APP_PASSWORD`. CI uses the temp keychain path (`setup` first). `bun run build:unsigned` skips signing.

## Commands
- `bun run dev` (window + HMR), `bun run serve:dev` (backend only, UI at http://localhost:5173 via `bunx vite`)
- `bun test` — unit tests (currently `src/ui/lib/__tests__`); the UI tsconfig excludes `__tests__`.
- `bun run typecheck` — two tsconfigs: root (backend, bun-types) and `src/ui/tsconfig.json` (DOM). Keep both green.
- `bun run build` — produces `dist/bin/drizzle-explorer` and the macOS `.app`.

## Conventions
- shadcn here is on **Base UI**, not Radix: use `render={<Comp />}` instead of `asChild`; Select needs `items` for labels.
- `react-resizable-panels` v4: numeric sizes are **pixels**, strings are percentages.
- Postgres connections (Bun SQL `connection.application_name`) and pg_dump/psql (`PGAPPNAME`) identify themselves as `Drizzle Explorer (<os user>)` via `server/identity.ts`.
- Raw SQL goes through drizzle `sql` templates; use `sql.identifier()` for user-supplied names. Never interpolate strings.
- Driver results must pass through `serializeRows()` (BigInt/Date/bytes → JSON-safe).
- Drizzle is `1.0.0-rc` (`drizzle-orm/bun-sql` = Bun's built-in SQL client; `drizzle-orm/bun-sqlite` = `bun:sqlite`).
- Test config dir: set `DRIZZLE_EXPLORER_CONFIG_DIR` so you don't touch `~/.config/drizzle-explorer`.
- Bun's Postgres client encodes bind params by the column type it gets from the prepared statement: JS numbers become `int` (rejected by boolean/numeric columns) and strings bound to `json/jsonb` become JSON *string* scalars. `PostgresDriver.insertRows` therefore binds text by default and coerces per target column (`paramCoercer`). Keep that in mind for any new write path.
- Anything that can run longer than a few seconds (dump, restore) must be a job (`startJob` in `server/jobs.ts`) polled via `jobs.status`; Bun.serve caps a single request at 255 s.
- The compiled app is minified: never branch on `error.constructor.name` or function names; use `instanceof` with your own classes (see `ReadOnlyRollback` in `drivers/postgres.ts`, which fixed every `run_query` failing in the packaged app).
- `objc_msgSend` has no fixed signature: declare it once per signature via separate `dlopen` calls (see `macos-menu.ts`).
- Paths from `import.meta.url` go through `fileURLToPath` (`new URL(...).pathname` yields `/D:/...` on Windows and broke the Windows release build); scripts spawn bun as `process.execPath` instead of relying on PATH.
- WKWebView applies macOS autocorrect/smart capitalisation to every field: `lib/no-autocorrect.ts` (installed in `main.tsx`) sets `autocorrect/autocapitalize/spellcheck` off on focus for inputs, textareas and contenteditable (AG Grid editors, CodeMirror), and the shadcn `Input`/`Textarea` carry the attributes explicitly.
